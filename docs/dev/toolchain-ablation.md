## 基线和方法

分支：`refactor/blog-toolchain`。Python 3.15.0、Hugo 0.148.2、Prettier 3.9.6，macOS。
每次只删除一个候选，执行基线、保存结果、恢复原文件，最后合并两项通过的删除。
基线依次执行：

```bash
make test
make check
make doctor
make build
python3 -B -m scripts warm-images --base HEAD
```

`warm-images --base HEAD` 验证无改动时跳过，不访问 CDN。构建使用真实 Hugo；
首次安装、Banner 请求和七牛请求使用隔离响应，不访问真实下载源或管理接口。
逐项实验用 Python `trace` 运行同一组入口，记录候选行是否执行；这不是分支覆盖率。
原始日志和每项删除 diff 的本机路径记录在 `.cache/ablation-study-path`，不作为永久依赖。

第一轮只有 35 个测试，十项删除中五项仍绿。其中安装器完全没有执行，
系统工具回退与暂存边界也缺少相应场景；这些绿灯未用于授权删除。
按用户要求补测后，45 个测试和上述基线全部通过，再重新做实验。

新增覆盖：空缓存安装与离线复用，macOS / Linux amd64 / Linux arm64 资产选择，
校验失败不覆盖原程序，系统同版本工具复用；Banner 抓取、缓存、丢图恢复、失败与代码围栏、
YouTube oEmbed；HTML/XML/Markdown/JSON 批量转换、二进制保持和幂等；
暂存文件在工作区被删，以及新分支首次推送的提交快照。

## 规模与结论边界

此前约 660 行 hack 脚本迁移后，scripts 实现约 1500 行，并增加回归测试。
新增安装、快照隔离、原子构建与发布后验收解释了一部分增长；目录统一本身不需要这么多代码。
本轮确实删掉了重复职责，但没有证实整个工具链已经足够简单。

两个较大的复杂度来源仍值得下一轮设计取舍：

- 自维护 Hugo 安装器：如果改用已有版本管理器或 CI 安装动作，需要同时给出本地安装替代路径，
  保持两个版本文件为唯一来源。这属于替换实现，超出本轮只删不改的消融范围。
- 可选七牛官方预热：当前没有配置密钥，默认发布只使用完整 GET。
  删除 API 模式将缩小已声明的功能，需要先明确是否取消该契约；隔离测试不能证明其业务必要性。

尚未验证真实首次下载、远端 Banner 网站兼容性、真实七牛受理及新 CI 的线上执行。
本轮没有上传图片、调用 CDN 管理 API、提交或推送。图片反复编码、缺图检查、Banner 缩略图与
下载哈希随后被缩图改写的问题仍独立存在，不能用本轮测试全绿掩盖。
